# 考场手机检测 —— 实验文档

> 赛题：在线考试手机检测（YOLO 格式，单类 `phone`，class_id=0）
> 环境：conda `det`（torch 2.6.0+cu124 CUDA 可用，ultralytics 8.4.60），GPU RTX 4090 D (24G)
> 更新日期：2026-08-28（B 榜收官）

---

## 1. 任务与评测协议（要点）

- **输出**：测试集每张图的目标框 `[x_min,y_min,x_max,y_max]`（像素）+ `confidence`(0~1) + `class="phone"`。
- **负样本（空标签图）**：必须返回 `"detections": []`；若提交非空检测，每个框计 FP。
- **评分公式**：`总分 = 100 × (0.5×mAP@0.5 + 0.3×Precision + 0.2×Recall)`
- **评测细节（本地复刻 `scripts/evaluate.py`）**：
  - IoU 阈值固定 **0.5**；置信度 **<0.25** 的预测框直接忽略（不参与任何指标）。
  - 重复框：预测按 conf 降序，每个 GT 只匹配第一个 IoU≥0.5 的框为 TP，其余 FP。
  - mAP@0.5 采用 **VOC2012 11 点插值法**（单类等价 AP@0.5）。
- **提交文件**：单个 UTF-8 JSON 数组，命名不限（如 `submit.json`）。

1. PIL 校验剔除 625 张损坏图片及其标签。

3. 标签越界行丢弃；固定 class_id=0。
4. 随机 8:2 划分 train/val（SEED=42），图级不重叠。

## 3. Baseline 方案

- **模型**：YOLO11s（ultralytics），输入 640，batch 32，100 epochs。
- **增强**：mosaic=1.0、mixup=0.1、copy_paste=0.1、hsv 抖动、fliplr，close_mosaic=15。
- **抗脏数据**：label_smoothing=0.1。
- **推理**：conf=0.05 全量输出，官方按 0.25 过滤；NMS IoU=0.5。

## 5. 得分差异分析（训练 / 验证 / 平台）

| 来源 | mAP@0.5 | Precision | Recall | 总分 | 说明 |
|------|---------|-----------|--------|------|------|
| 训练集 ultralytics val | 0.949 | 0.939 | 0.923 | — | 乐观值，默认 conf/NMS 与官方不同 |
| 本地验证集(官方协议) | 0.889 | 0.917 | 0.938 | 90.74 | 复刻官方 conf<0.25+IoU0.5+11点 |

**结论**：
1. 本地 `evaluate.py` 协议复刻准确（90.74 vs 90.81，误差 <0.1），后续优化可直接用本地验证集做迭代依据。

## 6. 下一步提分方案（按优先级）

- [x] **P0：更大输入分辨率**。640→**960/1280**，直接提升小目标与多尺度定位（预期 +1~2 分）。
- [x] **P0：更大模型容量**。YOLO11s→**YOLO11m**（参数量 ~20M→~42M），提升特征表达。
- [x] **P1：提交置信度阈值调优**。当前推理 conf=0.05 全量输出，官方过滤 0.25；在本地 val 扫描 conf∈{0.2,0.25,0.3,0.35} 选 P/R 最优平衡点（头部选手多次提交即在调此）。
- [x] **P1：测试时增强 TTA**（多尺度/翻转推理融合），提升 Recall 与稳定性。
- [ ] **P2：更强数据清洗**。漏标检测（用当前模型伪标签交叉验证找漏标补标）；难负样本（遥控器/耳机盒）挖掘降 FP。
- [ ] **P2：模型集成**。s+m 或多尺度权重融合。
- [ ] **提交物**：`submit.json` + 源码 + 说明 PPT（B 榜 8-27 开放，最终成绩以 B 榜为准）。

### 6.2 v2 (YOLO11m @ 960) 实验
- 训练 72 epoch 早停；ultralytics mAP50(B)=0.946，本地验证集(官方协议) mAP=0.8907, P/R 随 conf 变化。
- val 阈值扫描最优 conf=0.40，本地总分 **90.57**（略低于 baseline 调优 91.32）。
- **TTA（--augment）对 v2 无提升**（90.57 持平），说明瓶颈是定位精度本身而非推理抖动。
- **关键坑**：用 baseline 权重直接以 imgsz=1280 推理（训练时 640）导致 mAP 暴跌至 0.7549 —— 推理 imgsz 必须接近训练 imgsz，否则分布偏移严重退化。
- **结论**：mAP@0.5 锁在 0.89 是核心瓶颈（头部 93+ 意味 mAP≈0.93）。需从定位精度突破：更大训练分辨率(1280)+更长训练+漏标补标。

### 6.4 v3 (YOLO11m @ 1280) 实验
- 训练 88 epoch 早停（batch 因 OOM 自动降为 7）；ultralytics mAP50(B)≈0.943，本地验证集(官方协议) mAP=**0.8904**。
- val 阈值扫描最优 conf=0.35，本地总分 **90.82**（与 baseline 调优 91.32 相近，未显著超越）。
- **核心问题暴露**：baseline / v2 / v3 三模型在本地 val 的 mAP 都锁在 **0.890±0.001**，但 ultralytics 自带 mAP50(B) 分别为 0.949/0.946/0.943。
- **结论**：本地 `evaluate.py` 对 baseline 与平台实测(90.81 vs 90.74)高度吻合 → 本地 mAP=0.89 是真实水平，ultralytics 0.94 为乐观估计（默认 conf/NMS 不同）。**模型结构/分辨率提升已触及数据天花板（标注质量/漏标）**。

### 6.5 提分核心转向：数据质量（赛题隐含考点）
模型容量红利已耗尽（mAP 卡 0.89），下一步必须做**数据清洗**：
1. **漏标补标**：用当前最佳模型(v3)对训练集做伪标签，找出"高置信度检出但无标注"样本补标 → 直接增 Recall、降 FN。
2. **错标/偏移框修正**：置信度极低且尺寸异常的标注行复核。
3. **难负样本**：从无标签测试图挖掘相似物(遥控器/耳机盒)作为额外负样本训练，降 FP 提 Precision。
- 清洗后重新训练 v3 配置（1280, m），预期 mAP 突破 0.92、总分冲击 93+。

### 6.6 漏标补标实验（find_missed.py, v3 伪标签）
- 训练集 dry-run：负样本图 5692 中 **28 张**被高置信度(>0.5)检出（强烈漏标）；正样本图 **43 张**有未匹配高置信度(>0.6)检出（疑似漏标）。
- 已写回训练集标签（仅 train，val 保持纯净）。补标共 71 张图。
- 结论：漏标规模小（71/10959≈0.65%），不是 mAP 封顶主因；主因更可能是**定位精度/小目标/边界框偏移**及 val 标注同含噪声。
- 用补标后数据重训 v3 配置，观察 mAP 是否突破。

### 8.3 核心发现（全量 1955 张实测量化，8-27 19:12）
基于 `review_results.json` 实测（非外推）：
- **框级误检率 18.5%**（288 FP / 1555 预测框），外推全榜 ~436 个误检框。
- **空预测图完全漏检率仅 1.9%**（17/885），外推全榜 ~40 张完全漏检 → **负样本幻觉问题被严重高估**，模型几乎不在负样本乱画框。
- **有框图多手机漏检率 4.2%**（45/1070），外推 ~99 张漏检部分手机（展览柜/宣传画并排手机）。
- **漏标画框 119 个 + 漏检填数 120**，Recall 缺口主要在"多手机场景只检出部分"。

**FP 按置信度分布（修正早期小样本错觉）**：
`0.25-0.30:66, 0.30-0.35:60, 0.35-0.45:67, 0.45-0.60:67, 0.60+:28`
→ FP 在各区间**分布较均匀**，并非集中在低 conf。提阈值到 0.35 仅砍掉 **44%**（126/288）的 FP，非早期 140 张样本看到的 69%（小样本偏差）。
- 高 conf（≥0.35）仍有 162 个 FP，多为：手机局部重叠框（上半/下半身重复检）、笔记本/平板/遥控器误检。

**结论修正**：
1. 早期"低conf误检占69%+负样本大规模幻觉"是 **140 张小样本的偏差**，全量看不成立。
2. 模型 Precision 受 ~436 个散在误检框拖累（权重 0.3），这是 85 分的主因；Recall 实际不错（完全漏检<2%）。
3. B榜特有难点是**展览/宣传画多并排手机**（多手机漏检 4.2%），与训练集分布偏移最大。

### 8.4 对提分的启示
- **主路线：提 conf 阈值压 Precision**。当前提交 c0.25 融合版；实测提至 0.35~0.40 砍 ~44% FP、Recall 仅微损(<2%)，Precision 权重 0.3 → 预计可提 1~2 分。
  - 候选：c0.35 / c0.40 融合版（已有生成文件 `submit_B_5yolo_wbf_c0.25.json` 需重跑阈值版）。
- **次路线**：高 conf 重叠框用更严 NMS（iou=0.4）去重；笔记本/平板类误检难靠阈值，需后处理或接受。
- **多手机漏检**：TTA / 高分辨率推理可部分改善，但收益有限（仅 ~4% 图），优先级低于提阈值。
- 今日已交 2 发（c0.45=85.13, c0.30=84.22），剩 1 发额度（截止 8-28 17:00）。建议用最后 1 发试 **c0.40 融合版**验证提阈值收益。

### 10.2 自适应阈值思路（用户标注经验落地，标注集最优）
- **思路来源**：用户标注中发现——"单张图只检出 1 个手机"时模型偏保守（易漏检），宜**放低阈值**拉 recall；"检出 2 个及以上"时往往含误检/重复框，宜**抬高阈值**压 precision。
- **实现**：`scripts/predict_adaptive.py`，按每张图检出框数量分桶设 conf——单目标 `single_conf`，多目标 `multi_conf`。
- **breview 扫描最优组合**：单 c0.40 + 多 c0.60 → 94.37（高于任意固定 conf 的 93.95~94.14），验证思路在 clean 标注集有效。
- **平台实测**：90.90，比固定 c0.50(90.86) 仅 +0.04，提分微弱。说明 B 榜真实误差结构与该经验在标注子集上的表现不完全一致（B 榜未核查的 2488 张分布偏移更大）。

### 10.3 探索过但未上线的方向（breview 消融，均未带来有效增益）
| 方向 | 做法 | breview 结果 | 结论 |
|------|------|------------|------|
| 面积过滤 | `--min_area` 砍占图<2% 的框（治黑边误检） | 砍掉 Recall（有检测 52%→34%） | **放弃**，误砍真小目标手机 |
| WBF 融合 | yolo11m + yolo12s 多权重融合 | 92.74（< 11m 单模 94.09） | 负提升，同源 YOLO 错误相关 |
| TTA | `--augment` 多尺度翻转推理 | 50 分（坐标对齐 bug 崩溃） | 未修复；且 breview 上 R 已 0.97 无空间 |
| 自适应阈值 | 单 c0.40 / 多 c0.60 | **94.37** | 标注集最优，但平台增益有限 |

### 10.4 根因总结：为何卡在 ~91
1. **本地 breview 94.37 vs 平台 90.90，3.5 分缺口 = 未核查分布偏移**。
   人工核查仅覆盖 1955/4443 张（44%）；剩余 2488 张全量难样本（近景手持、宣传画并排手机、黑边图）分布与训练集偏差最大，模型泛化不足。
2. **伪标签污染已排除**：回流 1955 张 clean 标签后，breview 上 mAP 0.90+、P 0.97，证明 clean 模型 precision 健康；平台低分是真实未覆盖分布所致，非标签脏。
3. **模型容量 / 融合 / TTA 红利均已耗尽**：s→m→l→x 单模平台 90.81→91.43→91.35→91.32；异构融合、WBF、自适应阈值均只能在 ±0.3 内微调，无法突破分布鸿沟。
4. **真正缺口在"数据覆盖"**：B 榜特有的非监控视角（近景、宣传照）、多并排手机、letterbox 黑边图，训练集几乎未含 → 这是破 93 的唯一路径（更多 B 榜真实分布数据回流 + 针对性增强）。
